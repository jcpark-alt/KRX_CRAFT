2.1 초기화 구조 — IIFE 제거 · onpageload 단일 정의

항목변경 전 (W-Craft 산출물)변경 후
IIFE (function(){…})() / (async function(){…})() 자동 실행 명명 함수 scwin.init_* 로 분리 — 정의만 하고 자동 실행하지 않음
onpageload var __prev = scwin.onpageload; 오버라이딩 래핑 + 빈 스텁 생성 2구역 최상단 단일 정의, init_* 를 데이터 의존성 순서로 순차 호출
지연 처리 setTimeout 950/2400/5000ms 등 다중 예약으로 렌더 대기 선행 함수 완료 후 호출로 순서 보장 — 임의 지연 전부 제거
실행 순서 로딩 시점 자동 실행 + onpageload 시점 실행 혼재 전부 onpageload 진입 시 순차: 파라미터 수신 → 파생값 충전 → 렌더/조건 평가 
///////// 2. 초기화 영역 /////////
scwin.onpageload = function () {
    try {
        scwin.init_recvParam();  // 1) 파라미터 수신 (sysYear/listStatCd)
        scwin.init_fillNow();    // 2) sysYear 미수신 시 서버 연도 충전
        scwin.init_attrReals();  // 3) 안내 문구 동적 렌더
        scwin.init_conds();      // 4) 버튼/영역 표시 조건 평가
    } catch (ex) {
        $c.exception.handleError(ex, { context: "화면ID.onpageload" });
    }
};

2.2 오류 처리 — 진입점 try/catch + $c.exception.handleError

  • 진입점(3구역 이벤트 핸들러·onpageload)만 try/catch, catch 는 handleError 한 줄로 통일 (규칙 26).
  • 빈 catch·이중 중첩 try/catch 제거. 내부 업무 함수(4·5구역)는 예외를 삼키지 않고 전파.
  • 서브미션 함수(tx_fn_*)의 executeDynamic 자체 try/catch 제거 → 진입점 처리.

2.3 변수·문법

  • 엄격 비교: ==/!= → ===/!== (null/undefined 동시 판별 관용구 == null/!= null 은 유지).
  • const 기본: 재할당 없는 let/var 정리, 미선언 루프변수 for (i = … → for (let i = ….
  • 미사용 코드 삭제: 이벤트 핸들러의 미사용 지역변수(ev/event/__self), W-Craft 잔재 전역 재선언, 무의미한 자기 대입(scwin.fn_x = scwin.fn_x;).
  • 미참조 컴포넌트 캐싱 전역 삭제: W-Craft 가 body 전 컴포넌트를 scwin.X = $c.util.getComponent('X') 로 자동 캐싱한 것 중 미참조분(합계 140개) 삭제 — 실사용 캐싱·상태값·screenId 는 유지.

2.4 인라인 IIFE 전면 제거 → 명명 헬퍼 전환 2026-09-04 규칙 확정

  • 값 계산·값 쓰기용 인라인 IIFE 까지 전면 금지로 규칙을 확정하고 code-convention.md 에 반영.
