# HTTP 상태 코드 (Status Codes) 전체 마크다운 명세서

본 문서는 HTTP/1.1(RFC 7231) 및 최신 표준 규칙(RFC 6585, RFC 4918 등)을 기반으로 정의된 모든 HTTP 상태 코드를 누락 없이 하나로 통합한 마크다운 문서입니다. 

---

## 1xx : 정보 제공 (Informational Responses)
클라이언트의 요청이 서버에 접수되어 처리 중이며, 추가적인 액션이 필요함을 나타냅니다.

| 상태 코드 | 상태 메시지 (Status Text) | 상세 설명 (Detailed Description) | 주요 활용 및 비즈니스 의미 |
| :---: | :--- | :--- | :--- |
| **100** | Continue | 요청의 시작 부분이 서버에 정상 접수되었으니, 클라이언트가 나머지 요청 본문(Body)을 계속 전송해도 좋음을 알림. | 대용량 파일 업로드 시 `Expect: 100-continue` 헤더를 사전 전송하여 서버 수용 여부를 먼저 확인할 때 사용. |
| **101** | Switching Protocols | 클라이언트가 요청한 프로토콜 전환 요구를 서버가 승인하고, 다른 프로토콜로 변경 중임을 나타냄. | 일반 HTTP 요청을 **WebSocket 프로토콜**(`ws://`)로 업그레이드하고 커넥션을 유지할 때 필수적으로 발생. |
| **102** | Processing | 서버가 요청을 접수하여 처리 중이지만, 응답을 작성하기까지 시간이 다소 소요되어 타임아웃을 방지하기 위해 임시 응답을 보냄. | WebDAV 표준에서 사용되며, 시간이 오래 걸리는 일괄 작업 시 클라이언트가 연결을 끊지 않도록 유도. |
| **103** | Early Hints | 서버가 최종 응답을 준비하는 동안 브라우저가 링크 리소스(CSS, JS 등)를 사전 로딩(Preload)할 수 있도록 돕는 힌트 헤더 정보를 보냄. | 웹 페이지 로딩 속도 최적화(Link 헤더 전송 등) 및 클라이언트 렌더링 효율 향상에 활용. |

## 2xx : 성공 (Successful Responses)
클라이언트의 요청이 성공적으로 수신되었고, 이해되었으며, 최종적으로 수락되어 처리되었음을 의미합니다.

| 상태 코드 | 상태 메시지 (Status Text) | 상세 설명 (Detailed Description) | 주요 활용 및 비즈니스 의미 |
| :---: | :--- | :--- | :--- |
| **200** | OK | 요청이 성공적으로 처리되었음. 데이터 조회(GET), 수정(PUT/PATCH) 등이 완벽히 수행되었을 때의 표준 응답. | 가장 보편적인 성공 응답. 서버는 클라이언트가 요청한 리소스 본문(Body)을 함께 반환함. |
| **201** | Created | 요청이 성공적이었으며, 그 결과로 **새로운 리소스가 서버에 생성**되었음을 나타냄. | 회원가입 완료, 게시글 등록, 새 파일 업로드 등 **POST 요청**이 성공하여 새로운 ID나 URI가 생성되었을 때 반환. |
| **202** | Accepted | 요청이 접수(수락)되었으나, 실제 처리는 아직 완료되지 않았고 비동기적으로 진행될 예정임을 의미. | 배치 작업, 대규모 데이터 분석, 푸시 메시지 대량 발송 등 **비동기/큐(Queue) 처리 기반의 작업**에 사용. |
| **203** | Non-Authoritative Info | 요청은 성공했으나, 응답 헤더의 메타데이터가 원본 서버가 아닌 **프록시나 캐시 서버에 의해 수정**되었음을 나타냄. | 원본 서버의 응답을 중간 게이트웨이가 가공하여 전달하거나, 로컬 미러링 서버의 데이터를 반환할 때 발생. |
| **204** | No Content | 요청이 성공적으로 처리되었으나, 응답 본문(Body)에 클라이언트에게 **반환할 데이터가 없음**을 나타냄. | 데이터 삭제(DELETE) 성공 후 화면 이동이나 추가 정보가 필요 없을 때, 혹은 단순 상태 업데이트 성공 시 사용. |
| **205** | Reset Content | 서버가 요청을 성공적으로 처리했으며, 클라이언트에게 현재 요청을 보낸 문서 뷰(예: 입력 폼)를 초기화(Reset)하라고 지시함. | 웹 폼에 데이터를 입력하고 전송한 뒤, 사용자가 다른 데이터를 연이어 입력할 수 있도록 화면 폼을 비워줄 때 활용. |
| **206** | Partial Content | 클라이언트가 요청한 리소스의 **일부 범위(Range)만 성공적으로 반환**했음을 의미함. | 대용량 동영상 스트리밍 재생(오디오/비디오 분할 다운로드)이나, 이어받기 기능(Resume Download) 구현 시 필수적으로 사용. |
| **207** | Multi-Status | 여러 리소스에 대한 복잡한 작업 결과를 **하나의 XML/JSON 응답 바디 안에 여러 개의 상태 코드로 모아서 반환**함. | WebDAV 표준이나 일괄 데이터 처리(Batch API)에서 여러 건의 요청을 한 번에 보낸 후 각 건별 성공/실패 여부를 따로 알려줄 때 활용. |
| **208** | Already Reported | 이미 이전 응답 결과(Multi-Status 등)의 다른 부분에서 동일한 리소스 상태가 보고되었으므로 중복 응답을 생략함을 알림. | WebDAV에서 바인딩 컬렉션의 멤버들을 반복 확인하는 과정에서 중복된 출력을 방지하여 성능을 최적화하는 데 활용. |
| **226** | IM Used | 서버가 리소스에 대한 GET 요청을 완수했고, 클라이언트가 보유한 캐시 버전에서 변경된 델타(차이점) 결과만 반영했음을 의미. | HTTP 델타 인코딩 표준에서 네트워크 대역폭을 극도로 절약하기 위해 수정된 차이점만 전송할 때 사용. |

## 3xx : 리다이렉션 (Redirection Responses)
요청을 완료하기 위해 클라이언트 측에서 브라우저 주소 이동, 캐시 재사용 등 추가적인 조치를 취해야 함을 나타냅니다.

| 상태 코드 | 상태 메시지 (Status Text) | 상세 설명 (Detailed Description) | 주요 활용 및 비즈니스 의미 |
| :---: | :--- | :--- | :--- |
| **300** | Multiple Choices | 클라이언트가 요청한 주소에 대해 여러 개의 리소스 대안이 존재하여, 사용자가 하나를 선택해야 함을 알림. | 다국어 지원 페이지에서 사용자가 원하는 언어 버전(영어, 한국어 등)을 직접 선택하도록 유도할 때 드물게 사용. |
| **301** | Moved Permanently | 요청한 리소스의 URI가 **영구적으로 변경**되었음. 향후 모든 요청은 응답의 `Location` 헤더에 담긴 새 주소로 보내야 함. | 웹사이트 도메인을 변경했거나, 서비스 URL 구조를 전면 개편했을 때 **검색엔진 최적화(SEO) 점수 손실 없이** 연결할 때 필수적임. |
| **302** | Found | 요청한 리소스가 **일시적으로 다른 URI로 이동**했음을 의미함. (향후 주소가 다시 바뀔 수 있음) | 로그인 성공 후 원래 보던 페이지로 리다이렉트하거나, 일시적인 이벤트 페이지로 사용자를 유도할 때 전통적으로 사용. |
| **303** | See Other | 요청에 대한 결과를 다른 URL에서 확인해야 함을 나타내며, 브라우저는 반드시 **GET 메서드로 변경하여 재요청**해야 함. | POST 요청으로 리소스를 등록한 뒤, 새로고침 시 중복 등록되는 것을 방지하기 위해 결과 조회용 GET 페이지로 이동시킬 때(PRG 패턴) 사용. |
| **304** | Not Modified | 클라이언트가 보낸 요청 조건(If-Modified-Since 등)과 비교해 리소스가 변경되지 않았으므로, **로컬 캐시를 재사용**하라고 알림. | 서버의 대역폭을 극적으로 절약하며, 브라우저가 정적 자원(이미지, CSS, JS)을 빠르게 렌더링하도록 돕는 핵심 메커니즘. |
| **305** | Use Proxy | 요청한 리소스는 반드시 지정된 프록시 서버를 통해서만 접근할 수 있음을 나타냄. (현재는 보안 상의 이유로 브라우저에서 지원 중단됨) | 과거 특정 네트워크 대역 내의 게이트웨이를 거쳐야만 하는 자원에 대한 경로 지정용으로 사용되었음. |
| **306** | (Unused) | 과거 프로토콜 설계 단계에서 사용되었으나 현재는 사용되지 않는 예약된 코드 공간. | 표준 스펙상으로만 존재하며 실제 개발 및 서비스 운영 환경에서는 사용되지 않음. |
| **307** | Temporary Redirect | 302와 동일하게 임시 리다이렉션이지만, **클라이언트가 최초 요청 시 사용한 HTTP 메서드와 본문(Body)을 절대 변경하지 않고** 새 URL로 재요청해야 함. | 사용자가 결제나 폼 데이터 양식을 `POST`로 전송했을 때, 서버 측 경로가 변경되어도 안전하게 데이터를 유지한 채 재전송하도록 보장함. |
| **308** | Permanent Redirect | 301과 동일하게 영구 리다이렉션이지만, **HTTP 메서드와 본문(Body)을 그대로 유지**한 채 새 URL로 재요청해야 함. | `POST` 요청 경로가 영구적으로 바뀌었을 때, 데이터 유실이나 `GET`으로의 변조 없이 안전하게 주소를 강제 전환할 때 사용. |

## 4xx : 클라이언트 오류 (Client Error Responses)
클라이언트의 요청 문법이 잘못되었거나, 인증 정보가 누락되는 등 **요청 자체에 결함이 있어 서버가 처리를 거부**했음을 의미합니다.

| 상태 코드 | 상태 메시지 (Status Text) | 상세 설명 (Detailed Description) | 주요 활용 및 비즈니스 의미 |
| :---: | :--- | :--- | :--- |
| **400** | Bad Request | 요청 파라미터 누락, 유효하지 않은 JSON 포맷 등 잘못된 문법으로 인해 서버가 요청을 해석할 수 없음. | 프론트엔드에서 보낸 API 요청 데이터 규격이 백엔드의 Validation(유효성 검사) 규칙을 통과하지 못했을 때 반환. |
| **401** | Unauthorized | 해당 리소스에 접근하기 위해서는 **반드시 로그인이나 인증(Authentication)이 필요함**을 나타냄. | 토큰(JWT, OAuth)이 만료되었거나, 인증 헤더(`Authorization`)가 누락되어 비로그인 사용자가 제한된 API에 접근할 때 발생. |
| **402** | Payment Required | 서비스 이용을 위해 **결제가 필요함**을 나타냄. (초기 표준 설계 목적과 달리 현재는 플랫폼별로 커스텀하게 활용) | 구글 API나 OpenAI API 등에서 **크레딧 소진, 결제 연체, 유료 등급 전환 필요** 시 API 에러 코드로 간혹 활용됨. |
| **403** | Forbidden | 사용자의 신원은 확인되었으나(인증 성공), 해당 리소스에 접근할 수 있는 **권한(Authorization)이 없음**을 서버가 명시함. | 일반 회원이 관리자(Admin) 페이지 API를 호출하거나, 다른 사용자의 개인정보 조회를 시도할 때 차단용으로 반환. |
| **404** | Not Found | 요청한 URI에 해당하는 리소스를 서버에서 찾을 수 없음을 의미함. | 주소를 잘못 입력했거나, 데이터베이스에서 이미 삭제된 게시글 ID 조회를 요청했을 때 가장 흔하게 발생하는 에러. |
| **405** | Method Not Allowed | 요청한 주소(URI)는 존재하지만, 해당 리소스가 **지원하지 않는 HTTP 메서드**(예: GET 전용 주소에 POST 요청)를 사용함. | 라우팅 경로 설정 오류 혹은 특정 API의 허용 범위를 제한할 때 발생하며, 응답에 `Allow` 헤더를 포함해야 함. |
| **406** | Not Acceptable | 클라이언트가 요청 헤더(`Accept-*`)를 통해 지정한 데이터 포맷(예: JSON만 원함)을 **서버가 제공할 수 없음**을 나타냄. | 서버는 XML만 지원하는데 클라이언트가 `Accept: application/json`으로 요청했을 때, 호환 불가함을 명시적으로 거절하는 용도. |
| **407** | Proxy Auth Required | 401 인증 오류와 유사하지만, 요청을 처리하기 전에 클라이언트가 **프록시 서버의 인증을 먼저 완료해야 함**을 나타냄. | 기업 내부의 제한된 프록시 게이트웨이를 거쳐 외부 인터넷 망이나 특정 보안 망에 접속하고자 할 때 프록시 장비에서 반환함. |
| **408** | Request Timeout | 서버가 클라이언트의 요청이 완료되는 것을 기다리는 대기 시간이 초과되어 **서버 측에서 연결을 먼저 끊었음**을 알림. | 네트워크 상태 불안정으로 인해 요청 본문(Body) 패킷이 전송 기한 내에 전부 도착하지 못했을 때 발생함. |
| **409** | Conflict | 서버의 현재 상태와 클라이언트의 요청이 **충돌/모순**을 일으켜 작업을 완료할 수 없는 상태를 의미함. | 회원가입 시 **이미 존재하는 이메일/아이디**로 가입을 시도하거나, 동시성 제어로 인해 리소스 수정이 충돌했을 때 사용. |
| **410** | Gone | 요청한 리소스가 예전에는 존재했으나, 현재는 **영구적으로 삭제되었으며 포워딩할 주소도 없음**을 명시함. | 404와 유사하나, 고의로 리소스를 영구 파기했음을 기재하여 검색 엔진 로봇이 해당 주소의 수집을 영구히 중단하도록 유도할 때 유용. |
| **411** | Length Required | 서버가 요청을 수락하기 위해, 클라이언트가 반드시 응답이나 요청 헤더에 정확한 `Content-Length` 값을 지정해야 함을 요구함. | 요청 본문(Body)의 데이터 크기가 유효해야만 처리를 진행하는 특정 API 게이트웨이나 파일 수신 모듈에서 반환. |
| **412** | Precondition Failed | 클라이언트가 요청 헤더에 설정한 **전제조건(Conditional Header 등)이 서버 측 데이터와 일치하지 않아** 처리를 거부함. | 동시성 제어(Optimistic Locking) 시, 내가 읽었던 버전(`If-Match`)과 서버의 현재 데이터 버전이 달라 타인의 수정본을 덮어쓰지 않도록 방지할 때 사용. |
| **413** | Payload Too Large | 클라이언트가 보낸 **요청 본문(Body)의 크기가 서버가 허용하는 한계치보다 큼**. | 파일 업로드 API에서 서버가 제한한 용량(예: 10MB)을 초과한 대용량 파일을 전송했을 때 웹서버(Nginx 등) 단에서 즉시 차단하는 코드. |
| **414** | URI Too Long | 클라이언트가 요청으로 보낸 **URL 주소의 길이가 서버가 처리할 수 있는 최대 글자 수를 초과**했음을 나타냄. | GET 요청의 Query Parameter에 너무 많은 양의 데이터를 무리하게 텍스트로 직렬화하여 담아 보냈을 때 주로 발생. |
| **415** | Unsupported Media Type | 클라이언트가 전송한 데이터의 **미디어 타입(Content-Type)을 서버가 지원하지 않음**. | 서버는 `application/json`만 처리하도록 구현되어 있는데, 클라이언트가 `application/x-www-form-urlencoded`로 데이터를 보냈을 때 거절용으로 반환. |
| **416** | Range Not Satisfiable | 클라이언트가 요청한 리소스의 특정 범위(Range 헤더 값)가 서버의 전체 리소스 범위를 벗어나 유효하지 않음을 알림. | 100바이트 짜리 파일에 대해 `Range: bytes=500-1000`과 같이 데이터 유효 범위를 넘어서는 부분적 다운로드를 시도할 때 발생. |
| **417** | Expectation Failed | 요청 헤더의 `Expect` 필드에 명시된 전제조건을 서버가 도저히 만족시킬 수 없음을 나타냄. | 서버 환경이나 프록시 설정이 클라이언트가 바라는 특수한 패킷 전송 전처리 요구 사양을 충족시키지 못해 실패할 때 반환. |
| **421** | Misdirected Request | 클라이언트의 요청이 응답을 생성할 수 없는 엉뚱한 서버로 연결되었거나, 서버가 해당 도메인의 커넥션을 재사용할 수 없음을 의미. | HTTP/2 환경에서 하나의 커넥션으로 여러 도메인을 처리하려다 TLS 인증서 불일치나 라우팅 미스매치가 일어났을 때 발생. |
| **422** | Unprocessable Entity | 요청의 문법은 완벽하지만(400 에러 아님), **내부의 논리적 오류나 비즈니스 규칙 위반**으로 인해 명령을 수행할 수 없음. | WebDAV 및 복잡한 REST API에서 자주 쓰이며, 예를 들어 배송지 변경 요청 시 "이미 배송이 완료된 주문건"이라 변경할 수 없는 상황 등 논리적 예외 처리에 제격임. |
| **423** | Locked | 요청하고자 하는 대상 리소스가 현재 접근 금지 상태이거나 잠겨(Lock) 있어 수정할 수 없음을 나타냄. | 다중 사용자가 동시 편집을 진행하는 문서 관리 시스템(WebDAV 등)에서 특정 파일이 선점되어 잠겨있을 때 반환. |
| **424** | Failed Dependency | 이전 단계의 요청이 실패했기 때문에, 그 요청에 종속되어 있는 현재의 요청 작업 또한 도미노처럼 실패했음을 알림. | 트랜잭션 성격의 일괄 묶음 처리 중, 앞선 선행 작업이 오류(예: 400 등)를 일으켜 뒤따르는 하위 작업이 자동 무효화될 때 사용. |
| **426** | Upgrade Required | 현재의 프로토콜로는 요청을 완수할 수 없으니, 클라이언트가 더욱 최신의 프로토콜(예: TLS 1.3, HTTP/2)로 업그레이드해야 함을 강제함. | 보안이 취약한 옛날 버전의 프로토콜 통신을 차단하고 강제 프로토콜 규격 고도화를 요청할 때 서버가 전송. |
| **428** | Precondition Required | 서버가 요청을 처리하기 전에, 클라이언트 측에서 조건부 헤더(`If-Match` 등)를 필수적으로 제공해야 함을 명시함. | 동시성 제어가 필수인 민감한 자원 수정 API에서 클라이언트가 무조건 데이터 정합성 검증 헤더를 붙이도록 강제하는 장치. |
| **429** | Too Many Requests | 클라이언트가 지정된 시간 내에 **너무 많은 요청을 전송**했음을 나타냄. | **Rate Limiting(디도스 방지 및 API 사용량 제한)** 솔루션에서 과도한 트래픽을 유발하는 특정 IP나 계정을 일시 차단할 때 활용. |
| **431** | Request Header Fields Too Large | 클라이언트가 보낸 요청 헤더 항목들의 크기 총합, 혹은 특정 단일 헤더의 글자 수가 서버 허용 용량을 초과함. | 브라우저 쿠키(Cookie)에 너무 많은 세션 데이터가 쌓여 헤더 크기가 비대해졌을 때 웹서버 단에서 차단하는 에러. |
| **451** | Unavailable For Legal Reasons | 정부 규제, 법적 소송, 저작권 침해 판결 등 **법률적인 사유로 인해 해당 리소스에 대한 접근이 전면 차단되었음**을 의미함. | 불법 사이트 차단(워닝 패널 등)이나 국가별 검열, 저작권 권리 위반으로 인해 서비스가 공식적으로 금지된 주소 요청 시 사용. |

## 5xx : 서버 오류 (Server Error Responses)
클라이언트의 요청은 정상적이었으나, **서버 내부의 시스템 결함, 데이터베이스 에러, 인프라 장애 등으로 인해 요청을 완수하지 못함**을 의미합니다.

| 상태 코드 | 상태 메시지 (Status Text) | 상세 설명 (Detailed Description) | 주요 활용 및 비즈니스 의미 |
| :---: | :--- | :--- | :--- |
| **500** | Internal Server Error | 서버 내부 로직이나 소스 코드 오류, 예외 처리되지 않은 버그 등으로 인해 서버가 작동 불능 상태에 빠짐. | 백엔드 코드의 NullPointerException, SQL 구문 에러, 치명적인 비즈니스 로직 예외 발생 시 반환되는 포괄적 에러. |
| **501** | Not Implemented | 클라이언트가 요청한 기능이나 메서드를 **서버가 아직 구현하지 않았거나 지원하지 않음**. | 서버 소스 코드 상에 API 라우터 규격만 선언해 두고 실제 내부 비즈니스 로직 핸들러는 개발 단계(TODO)일 때 주로 반환. |
| **502** | Bad Gateway | 게이트웨이나 프록시 서버가 상위 서버(WAS 등)로부터 유효하지 않은 응답을 받았음을 의미함. | Nginx나 Apache 같은 웹서버가 뒤단의 Tomcat, Node.js, Spring Boot 애플리케이션이 죽어있어 통신 실패할 때 발생. |
| **503** | Service Unavailable | 서버가 현재 과부하 상태이거나 계획된 정기 점검/유지보수 중이어서 **일시적으로 서비스를 제공할 수 없음**. | 시스템 점검 안내 페이지를 띄우거나, 트래픽 폭주로 인해 서버 리소스가 고갈되었을 때 서킷 브레이커가 반환하는 코드. |
| **504** | Gateway Timeout | 게이트웨이나 프록시 서버가 상위 백엔드 서버의 응답을 기다리다가 **지정된 제한 시간(Timeout)을 초과**함. | 백엔드 데이터베이스의 복잡한 쿼리가 무한 루프에 빠졌거나, 외부 API 연동 시 응답이 오지 않아 프록시 단에서 먼저 연결을 끊을 때 발생. |
| **505** | HTTP Version Not Supported | 클라이언트가 요청에 사용한 **HTTP 프로토콜 버전**(예: HTTP/3)을 서버가 지원하지 않거나 거부할 때 반환. | 레거시 서버 장비에 최신 고속 프로토콜로 통신을 시도했을 때 하위 호환 매칭이 이루어지지 않아 거절하는 경우 발생. |
| **506** | Variant Also Negotiates | 서버 내부의 투명한 콘텐츠 협상(Content Negotiation) 프로세스 중 라우팅 설정 오류로 인해 **순환 참조(지속적 내부 리다이렉트)** 오류가 발생함. | 서버 내부 설정 오류로 응답 가능한 자원들이 서로를 다시 호출하는 무한 루프 상태에 빠졌음을 감지하여 차단할 때 반환. |
| **507** | Insufficient Storage | 서버가 요청을 성공적으로 완료하는 데 필요한 **디스크 공간이나 스토리지 메모리 자원이 부족**할 때 발생함. | 파일 업로드나 데이터 저장 처리를 하려는데 서버 인프라 장비의 디스크 용량이 100% 꽉 차서 쓰기 작업을 수행할 수 없는 하드웨어 에러. |
| **508** | Loop Detected | 서버가 요청을 처리하는 과정에서 **무한 루프(Infinite Loop)나 리다이렉션 체인 오동작을 감지**하여 강제 중단했음을 알림. | WebDAV 컬렉션 관계 설정 미스로 하위 폴더가 상위 폴더를 참조하는 등의 디렉토리 구조적 무한 순환을 예방하는 코드. |
| **510** | Not Extended | 클라이언트가 보낸 요청을 수행하기 위해 서버 측에서 요구하는 추가적인 프로토콜 확장 사양이 만족되지 않았음을 뜻함. | 특수 확장 정책 정보나 규격 헤더가 누락되어 백엔드 코어가 더 이상 분석 처리를 이어나갈 수 없을 때 반환. |
| **511** | Network Auth Required | 클라이언트가 네트워크 망을 원활하게 이용하기 위해 **최초의 네트워크 인증(로그인 등)이 선행되어야 함**을 강제함. | 공공 와이파이(Wi-Fi), 공항/호텔 등의 캡티브 포털(Captive Portal) 환경에서 인터넷 서핑 시작 전 사용자 인증 동의 페이지를 띄우기 전에 반환. |
