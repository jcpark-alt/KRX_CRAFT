iframe 내부 페이지에서 부모 팝업 창을 닫는 처리 흐름

작성일 2026-09-16 · WebSquare 팝업(XML) 안의 iframe 페이지 → postMessage → 부모가 $c.win.closePopup 실행

1. 전체 연동 흐름 요약

[1. 팝업 XML (Parent Window)]
   │
   ├─ $c.win.getPopupId()로 popupId 획득
   ├─ iframe src URL 뒤에 ?popupId={popupId} 전달
   └─ window 'message' 이벤트 리스너 등록 (수신 대기)

[2. iframe 내부 페이지 (Child Window)]
   │
   ├─ URL 쿼리 파라미터에서 popupId 추출
   └─ 닫기 버튼 클릭 시 sendPopupMessage() 실행 → postMessage 전송

[3. 팝업 XML (Parent Window)]
   │
   └─ postMessage 수신 후 $c.win.closePopup($p, popupId) 실행하여 팝업 종료

2. 단계별 상세 코드 정리

1팝업 XML (부모 창)

iframe을 포함하고 있는 팝업 페이지에서 popupId를 구하여 iframe URL에 파라미터로 붙여주고, 자식 창에서 전달되는 메세지를 수신하도록 설정합니다.

// 1. 팝업 ID 획득
const popupId = $c.win.getPopupId();

// 2. iframe URL에 popupId 전달 (예시)
const iframeEl = document.getElementById("myIframe");
iframeEl.src = `/path/to/page.html?popupId=${encodeURIComponent(popupId)}`;

// 3. postMessage 수신 이벤트 리스너 등록
window.addEventListener('message', (event) => {
  // [보안] 필요한 경우 Origin 검증 추가
  // if (event.origin !== 'https://your-domain.com') return;

  const { execution, popupId } = event.data;

  // 팝업 닫기 요청 처리
  if (execution === "closePopup" && popupId) {
    console.log(`수신된 Popup ID: ${popupId}`);
    $c.win.closePopup($p, popupId);
  }
});

2iframe 내부 페이지 (자식 창)

iframe 내부에서 팝업을 닫는 이벤트(예: 닫기/확인 버튼 클릭)가 발생할 때 호출할 함수입니다.

/**
 * URL 파라미터에서 popupId를 가져와 상위 창 (Parent Window)으로 메시지를 전송하는 함수
 * @param {Object} [payload={}] - 함께 전달할 추가 데이터
 * @param {string} [targetOrigin='*'] - 메시지를 수신할 상위 창의 Origin
 */
function sendPopupMessage(payload = {}, targetOrigin = '*') {
  // 1. 현재 URL의 쿼리 파라미터에서 popupId 추출
  const urlParams = new URLSearchParams(window.location.search);
  const popupId = urlParams.get('popupId');

  // 2. popupId 유효성 검사
  if (!popupId) {
    console.warn('URL 파라미터에서 popupId를 찾을 수 없습니다.');
    return;
  }

  // 3. 전달할 메시지 데이터 구성
  const messageData = {
    execution: 'closePopup',
    popupId: popupId,
    ...payload
  };

  // 4. 상위 창(Parent Window)으로 메시지 전송
  window.parent.postMessage(messageData, targetOrigin);
}

3. 핵심 포인트

  • 안전한 데이터 전달: iframe 간 직접적인 스크립트 접근 대신 웹 표준인 postMessage API를 사용하여 도메인이 다르더라도(Cross-Origin) 안전하게 통신할 수 있습니다.
  • 유연한 데이터 확충: sendPopupMessage({ result: 'SUCCESS' })와 같이 호출 시 payload 객체를 전달하면, 팝업을 닫으면서 부모 창에 결과값이나 처리 상태를 함께 전달할 수 있습니다.
  • 보안 권장사항: 운영 환경에서는 targetOrigin과 event.origin 검증을 특정 도메인(예: https://example.com)으로 제한하는 것이 안전합니다.
참고 — WebSquare 엔진도 iframe 클릭·마우스다운·키업 전파용으로 { _wq_type: … } 객체를 postMessage 로 보낸다. 부모의 message 리스너는 위 코드처럼 execution === "closePopup" 조건으로 자기 메시지만 골라 처리하고, event.data 가 객체가 아닐 수 있으므로 구조 분해 전에 형태를 확인하면 더 안전하다.
