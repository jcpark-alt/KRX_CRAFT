KRX 상장공시 제출시스템 — 웹스퀘어 전환 개요

소스 전달·검토 동봉용 요약 (2026-08-17 갱신).

1. 무엇을 했나

as-is JSP/JSTL 화면 2,104종을 웹스퀘어(WebSquare) 화면으로 전환했습니다. 화면을 하나씩 손으로 옮긴 것이 아니라, as-is 를 해석해 중립 스펙으로 옮기고 그 스펙에서 웹스퀘어를 생성하는 파이프라인을 만들어 전판을 일괄 생성합니다. 규칙을 한 줄 고치면 2,104종에 즉시 반영됩니다.

2. 파이프라인

as-is (JSP·JSTL·struts·tiles)
        │  ① 추출  — 화면을 "무엇인가"로 해석
        ▼
   중립 스펙 (표준 어휘 · 프레임워크 무관)
   A1 컴포넌트 트리 · A2 역할 · C1 데이터 스키마 · C2 데이터 흐름
   C4 서버 전문 · D 페이지 그래프 · G1 라이프사이클 · G2 레이아웃
        │  ② 생성  — 스펙만 보고 웹스퀘어를 만든다 (as-is 를 다시 보지 않음)
        ▼
   웹스퀘어 XML  →  ③ W-Pack 컴파일(.js)  →  ④ 배포
        │
        └─ ⑤ 검증: 실브라우저 렌더 · 원본 대조 · 규칙 게이트

핵심 설계 두 가지

  • 중립 스펙 · 표준 어휘 — 스펙에는 웹스퀘어 용어가 없습니다. "입력상자·표·목록·조건·반복" 같은 표준 어휘만 담고, 웹스퀘어로 바꾸는 지식은 생성기 쪽에만 둡니다. 그래서 as-is 해석과 to-be 생성이 분리됩니다.
  • 매핑표(카탈로그) 우선 — 화면마다 코드를 고치지 않고 표를 고칩니다. 표 한 줄이 전판에 퍼집니다.

4. 데이터·전문 축

as-is 화면에서 서버 전문(인터페이스) 을 역산해 사전 DB 에 등재했습니다.

  • Message(서버 통신 단위) 168종 · DataEntity(업무 데이터 정의) 529종 · 코드그룹 136종
  • 화면의 데이터 바인딩이 C4 전문 → C1 엔티티 → 데이터셋 → 컴포넌트 ref 로 한 이름으로 관통합니다 (전판 참조 15,890건 · 끊긴 참조 0)
  • 데모는 mock 데이터로 돌리고, 전달 소스는 실서버 호출형(prod)입니다. 실제 전문 정의서를 받으면 이름만 갈아끼우면 사슬이 따라옵니다

5. 공통 자원·셸

  • KRX 수령 셸 원본은 무수정입니다. 초기 로딩·메뉴·전체메뉴처럼 원본이 목업으로 남긴 자리는 우리 층(글루)에서만 보완했습니다.
  • 공통함수($c) 규격 494종을 등재해 생성이 소비합니다.
  • 재사용 화면 컴포넌트(UDC)를 합성해 전 화면에 공유합니다.

6. 검증 체계

  • 실브라우저 렌더 검증 — 화면을 실제로 띄워 확인합니다(정적 문자열 대조에 기대지 않습니다)
  • 원본 대조 — 작업본(보내주신 샘플 6개)/전환본 소스 비교(표시 라벨·태그 구조·데이터 축)
  • 규칙 게이트 — 표준 어휘 위반·스펙 정합·컴파일 실패를 자동 차단
  • 배포 자동화 — 전판 컴파일·배포·원격 서버 동기화

7. 현재 상태

  • 전판 2,104종 생성·배포 완료 (실패 0) · 동봉 소스 = 샘플 6종+참조 화면 28화면 prod 판(자동 검문 통과)
  • 화면 확인용 데모 서버 가동 — 전체메뉴에서 작업본(보내주신 샘플 6개)과 전환본을 나란히 열어 비교할 수 있고, 메뉴 검색을 지원합니다
  • 작업 진행 중이라 미완성 화면이 있습니다 — 아래 미해결 축이 그 원인입니다
