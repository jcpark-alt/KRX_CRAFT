API.md 생성기

저장한 RapiDoc API 문서(HTML)에서 고른 API 의 요청·응답 표를 읽어, 전환용 {화면ID}_API.md 를 만듭니다.

입력

선택한 파일 없음
브라우저에서 API 문서를 연 뒤 「다른 이름으로 저장(웹페이지, 전체)」한 HTML 입니다. 서비스가 다르면 여러 파일을 함께 고릅니다.
문서 URL(# 뒤 앵커), GET /api/…, get-/api/…, 경로만(method 전부), 화면ID(요약에 그 화면ID 가 든 API 전부)를 섞어 적을 수 있습니다.
생성 규칙 
블록 머리   ## n. {요약}            (요약 = 문서의 API 제목, 예: [ULDSTF05702][업무][제목] 상세 조회)
AS-IS       문서의 API 설명 전체     (설명에 "AS-IS fn_xxx" 를 적어 두면 그대로 옮겨진다)
TO-BE       {METHOD} {경로}

id 이름     경로 끝 단어에서 "select-" 를 떼고 camelCase
              select-list → list · select-list-releas-isu → listReleasIsu
              select-one → detail · check-double-input → checkDoubleInput
            응답 object → dma_{이름}, array → dlt_{이름}
            하위 object/array 필드 → dma_/dlt_{이름}{필드}  (target "…=body.{필드}")
            요청 본문이 있는 API 의 응답은 {이름}Result
dataType    integer·number → number, 그 밖(string·boolean·[string]) → text
name        필드 설명 (➔·Constraints·Examples 표기는 뺀다)

GET 쿼리    const requestData = { 파라미터: "" }
POST 본문   평면 object → 요청 dataMap + ref
            하위 구조가 있으면 dataMap/dataList 여러 개 + requestData 조합
              (object → .getJSON(), array → .getAllJSON())

id 는 규칙으로 제안한 이름입니다. 화면에서 쓰는 이름(예: dlt_list·dma_detail)이 따로 있으면 결과에서 고친 뒤 저장합니다. 결과 영역은 직접 고칠 수 있습니다.
