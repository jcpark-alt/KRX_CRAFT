요청하신 내용을 반영하여 "api-doc.html은 샘플이며 실제 URL은 API 항목마다 상이하다"는 조건을 추가해 프로세스를 다시 정리했습니다.

---

### 🎯 최종 목표

여러 개의 API 문서 URL을 입력받아 해당 스펙을 크롤링/파싱한 뒤, 연동에 필요한 데이터 객체 구조와 최종 `API.md` 문서를 자동 생성해 주는 **HTML 기반의 자동화 유틸리티 제작**

### ⚙️ 단계별 구현 프로세스

**1. 타겟 식별 및 DOM 탐색 (파싱 기초 단계)**

* **URL 패턴 분석:** `api-doc.html#get-/api/...` 와 같이 호출 방식(GET/POST 등)과 엔드포인트가 결합된 URL 해시(#) 앵커 패턴을 식별합니다. **(단, `api-doc.html`은 이해를 돕기 위한 샘플 파일명이며, 실제 호출되는 문서의 URL은 API 항목마다 상이하므로 다양한 URL 주소에 동적으로 대응할 수 있도록 처리합니다.)**
* **요소 검색:** 추출한 해시 문자열을 활용하여 타겟 URL의 DOM 내에서 `id="get-/api/.../select-one"` 속성을 가진 특정 API 설명 블록(Element)을 탐색합니다.

**2. 스펙 추출 및 프론트엔드 연동 데이터 매핑 (UI 객체 정의 단계)**

* **데이터 추출:** 검색된 요소의 하위 노드를 탐색하여 REQUEST(요청 파라미터) 및 RESPONSE(응답 데이터) 스펙 정보를 스크래핑합니다.
* **dataCollection 정의:** 추출된 스펙을 기반으로 화면단에서 사용할 `dataCollection`(DataMap, DataList 등) 생성 코드를 자동 구성합니다.
* **Submission 매핑:** 동적 통신 함수인 `$c.sbm.executeDynamic`을 호출할 때 필요한 `ref`(요청 데이터 객체)와 `target`(응답 데이터 객체) 속성 바인딩 구조를 정의합니다.

**3. 마크다운(Markdown) 자동 생성 로직 구현 (출력 단계)**

* **템플릿 분석:** 기존 샘플인 `파일명_API.md` 문서를 분석하여, 추출한 REQUEST/RESPONSE 및 API 메타 정보가 매핑될 마크다운 템플릿 구조(포맷)를 설계합니다.
* **생성기 개발:** 분석된 템플릿에 스크래핑한 데이터를 치환하여 텍스트로 렌더링하는 로직을 구현합니다.

**4. 자동화 툴 통합 (최종 HTML 유틸리티 완성)**

* 사용자가 상이한 구조를 가진 다수의 API URL을 한 번에 입력할 수 있는 UI를 구성합니다.
* 입력된 URL들을 순회하며 1~3번의 과정을 반복 수행하여, 병합된 형태의 최종 `API.md` 결과물을 화면에 출력하거나 파일로 다운로드할 수 있도록 완성합니다.
