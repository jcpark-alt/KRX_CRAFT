가르는 규칙은 전부 as-is 파일에 있는 사실만 씁니다.

- forward 가 다시 `.do` 이면(저장 뒤 재조회 redirect) 이동으로 내지 않습니다.
- 폼 `target` 이 같은 문서의 `<iframe name>` 과 같으면 **이동이 아닙니다** — 숨은 프레임 제출이라
  화면은 그대로입니다.
- 목적지 후보가 여럿이어서 하나로 못 정하면 **모호로 두고 지우며**, 화면별 진단 파일에
  `unresolved:nav:<action> — 이동 목적지를 하나로 못 정한다(후보 N: …)` 로 남깁니다.
- 옛 해석이 가리키던 화면이 전달 범위에 **없으면** 그 이동도 걷습니다(없는 곳으로 보내지 않습니다).

**「제출 + 이동」 배선** — 저장·삭제처럼 고치는 동작은 **서버 호출을 먼저 하고, 성공했을 때만** 목록으로
이동합니다. 실패하면 이동하지 않습니다.

```
$c.util.getComponent('dma_fncSearchReq').set('method', 'deleteCorpList');
{ const nr = await scwin.tx_fncDelete();
  if (nr && nr.responseJSON && nr.responseJSON.success === true) {
    $c.win.moveUrl("/corplist/corplist.xml", { "method": 'deleteCorpList' }); } };
```

**화면에서 어떻게 보이나** — 버튼을 눌렀을 때 ⑴ 서버 호출이 나가고 ⑵ 성공하면 목적 화면으로 넘어갑니다.
종전 판에서 「눌러도 아무 일도 없던」 자리가 대부분 해소되었습니다(전판 실측: 이동 지정은 있는데 이동
호출이 없던 자리 **126 → 15**). 서버 호출 수 **2,855 → 3,192**, 이동 호출 수 **332 → 407** 입니다.

**영향 파일** — 화면 XML 의 스크립트 절, 그리고 화면별 추출 진단 파일.

### 1-2. 오류 알림이 「사유」를 말합니다

**무엇이 바뀌었나** — 아직 전환되지 않은 자리는 종전에 `throw new Error("unresolved:…")` 였고,
공통 `handleError` 가 기본 문구 「처리 중 오류가 발생했습니다.」만 띄웠습니다. 사용자는 **무엇이 안 됐는지
알 수 없었습니다.**

공통 함수 계약을 그대로 씁니다 — `handleError` 는 `ex.bizMessage` 가 있으면 그 문구로 알립니다.
그래서 던지는 값에 문구를 담았습니다.

```
throw { bizMessage: "보낼 입력값을 아직 읽지 못합니다(전환 미완) — S_DATE, E_DATE",
        unresolved: "query_param:S_DATE,E_DATE" };
```

세 자리에 적용했습니다 — 제출 주소를 못 정한 자리 · 목적지 주소를 못 찾은 자리 · 보낼 입력값을 아직
읽지 못하는 자리.

**감추는 것이 아닙니다** — 여전히 예외를 던지고 여전히 실패하며, 기계가 세는 표지(`unresolved`)도
그대로 남습니다. 달라진 것은 **사용자에게 사유가 보인다**는 점뿐입니다.

**화면에서 어떻게 보이나** — 미전환 자리를 누르면 표준 알림창에 한국어 사유가 나옵니다.
**영향 파일** — 화면 XML 의 스크립트 절.

### 1-3. 초기화 없는 최상위 변수 선언도 살립니다

**무엇이 바뀌었나** — as-is 의 `var obj;` · `var selId;` 처럼 **초기값이 없는** 최상위 선언을 추출기가
버려서, 전환 산출에서 그 이름이 **선언 없이 사용**되고 있었습니다(`authselectpop` 실측: `obj` 4회 ·
`selId` 2회 사용, 선언 0회). 대상은 **10자리**입니다.

이제 이름만 담아 선언을 냅니다 — **값은 지어내지 않습니다**(`scwin.obj = undefined;`).

**화면에서 어떻게 보이나** — 해당 화면에서 「정의되지 않은 이름」으로 스크립트가 끊기던 자리가 없어집니다.
**영향 파일** — 화면 XML 의 스크립트 절.

### 1-4. 선택 상자의 코드 목록을 데이터로 냅니다

**무엇이 바뀌었나** — 코드 목록을 쓰는 선택 상자의 선택지가 **마크업에 굳어**(`<w2:item>`) 있었습니다.
이제 `dlt_code_<이름>` dataList(열 `cdId` = 값 / `cdVal` = 라벨) + `<xf:itemset>` 으로 냅니다.
빈 첫 항목(「— 선택 —」)도 첫 행으로 함께 싣습니다 — 버리면 필수 선택이 되어 as-is 동작이 바뀝니다.

**화면에서 어떻게 보이나** — 선택지 개수와 순서는 그대로입니다(격리 실측: 18 == 18). 달라진 것은
선택지가 **데이터로 분리되어** 뒤에 서버 코드 조회로 갈아 끼울 수 있다는 점입니다.

⚠ **이번 전달 범위에는 해당 자리가 아직 0건입니다.** 코드 목록 원천(공통코드 전문)을 받으면 그때
같은 기구로 채워집니다. 방출 경로만 미리 갖춘 것이라 **이번 판 산출에는 변화가 없습니다.**

**영향 파일** — (해당 자리가 생기면) 화면 XML 의 마크업과 dataList 선언.

### 1-5. 생성 일자 주석을 고정했습니다 — 판 사이 비교가 가능해집니다

**무엇이 바뀌었나** — `meta_date` 속성과 함수 머리말의 `@date` 가 **생성 시각(`new Date()`)** 을
썼습니다. 그래서 같은 입력·같은 생성기인데도 **날이 바뀌면 전판 파일이 전부 달라 보였습니다.**
이제 원천을 **추출 시각(스펙의 `extracted_at`)** 으로 고정했습니다. 없으면 지어내지 않습니다 —
`meta_date` 는 빈 값, `@date` 줄은 생략합니다.

**화면에서 어떻게 보이나** — 변화가 없습니다.
**무엇이 좋아지나** — 「우리 판 대비 몇 줄이 바뀌었나」를 **파일 해시로 바로 대조**하실 수 있습니다.
같은 스펙을 두 번 생성하면 해시가 같습니다(격리 실측 8/8).

**영향 파일** — 모든 화면 XML 의 머리(meta) 영역과 스크립트 주석.

### ⭐8 에 대하여 — 포커스 이동
웹스퀘어 엔진의 표준 이름은 `setFocus` 가 **아니라 `focus`** 입니다(입력 상자·달력·라디오·이미지 전부).
`setFocus` 는 네 컴포넌트(`selectbox`·`pageList`·`includeFrame`·`window`)에만 있습니다.
우리 변환이 **둘 다 시도하도록** 냅니다 — 앞의 이름이 없으면 뒤의 이름을 부릅니다.
```js
(X && X.setFocus ? X.setFocus() : (X && X.focus ? X.focus() : console.warn('[sdd] focus 대상 미해결: <id>')))
```
⇒ 달력 12자리·이미지 1자리는 `setFocus` 가 없지만 ⭐**`focus()` 로 실제로 포커스가 갑니다**(런타임 실측).
**포커스가 안 가는 자리는 없습니다.**

### ⭐10 에 대하여 — 주석 뒤 문장이 삼켜져 있었습니다
as-is 스크립트는 옛 관용구로 **HTML 주석**을 씁니다(`<!-- 신규작성인지 체크 -->`). 우리 변환이 그것을
주석이 아니라 **식**으로 읽어, 어떤 화면에서는 **그 뒤에 오던 문장까지 함께 삼켰습니다**.
전판을 다시 뽑으니 그 자리가 드러났습니다 — **삭제 14,708줄 / 복원 1,167줄**.
⇒ 주석 다음 줄에 있던 **실제 처리**가 되살아납니다.

### ⭐11 에 대하여 — 파일 첨부
as-is 는 `if ( fileSize / 1024 > ${fileLimitSize} )` 처럼 **JSP 식을 자바스크립트 안**에 씁니다.
그 식을 우리 변환이 조건의 일부로 읽지 못해 **조건 뒤 문장 전부가 조건 밖으로** 나왔습니다.
그래서 파일을 고르면 **항상** 「최대 크기는 30M를 넘을 수 없습니다」가 뜨고 입력칸이 비워졌습니다.
값은 지어내지 않고 **그 화면의 `<c:set var="fileLimitSize" value="10240"/>` 선언 값**으로 풀었습니다.

⭐**다섯째는 이번 판에서 새로 «드러나게» 만든 것입니다.** 종전에는 그 자리에 **주석만** 있어
(`/* unresolved-target intent:set_focus … */`) 화면에서도 콘솔에서도 **아무 표시가 없었습니다** —
커서가 안 옮겨지거나 영역이 안 열려도 «조용히» 지나갔습니다. 그중 **168자리는 곁에 다른 표시도 없어
완전히 무증상**이었습니다. 이제 전부 콘솔에 남습니다(동작 종류별: 포커스 이동 584 · 영역 표시/숨김 82 ·
라벨 변경 28 · 행 삭제 1). ⛑화면 동작은 **바뀌지 않습니다** — 콘솔에만 남습니다.
**빈 함수·빈 `catch` 로 덮은 자리는 없습니다.** 위 문구가 보이면 그 자리는 **아직 전환되지 않은 것**입니다.

### 닫을 수 없는 자리 1 — 이름 안에 JSP 식이 든 경우
```
as-is:  std_cd_apct_tp_cd_${row.cd_val}.focus();
```
`row` 는 목록 반복 변수라 **그 이름이 행마다 다릅니다**. as-is 에서는 JSP 가 행마다 하나씩 만들었지만,
웹스퀘어에는 그런 이름이 없어 **지어낼 수 없습니다**.
⇒ 그 함수는 as-is 원문 경로로 내보냈고, **산출 자체는 정상**입니다(변환이 그 자리를 기본 항목의
표준 포커스 호출로 풀었습니다). ⚠다만 **행별 구분이 사라져 포커스가 「그 행」이 아니라 기본 항목으로** 갑니다.

적어 두면 어느 쪽이 최신인지 알 수 없어 한 곳으로 합쳤습니다.
