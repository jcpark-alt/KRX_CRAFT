3. 향후 실행 방안 (Action Plan)

3.1 하네스 및 Skills 구축

  • sample-front의 작성 규칙(화면 골격, head 메타, 영역별 레이아웃 패턴)을 문서화하고 퍼블리싱 전용 Skill로 만듭니다.
  • 참조 파일에 없는 코드(스크립트, 임의 컴포넌트, 스타일)를 생성하지 못하도록 금지 규칙을 명시합니다.
  • 생성한 뒤 정적 검증을 자동으로 수행합니다. 예: wsxml_lint 결과 0 오류, 0 경고

3.2 컴포넌트 선택 프롬프트 명확화

gridView

  • 조회 결과 목록
  • 반복 행 데이터
  • 행 추가·삭제·편집이 필요한 영역

Table

  • 조회 조건 영역
  • 단건 상세·입력 폼
  • 고정된 라벨-값 배치
  • 요청 프롬프트에 영역별 컴포넌트를 명시하는 템플릿을 표준화합니다(특히 Fable 5.1에 적용).

3.3 모델 운영 기준 (제안)

  • 기본 생성은 Opus 5.5 또는 Fable 5.1로 하고, 컴포넌트를 명시한 프롬프트 템플릿을 함께 씁니다.
  • Sonnet 5.5는 하네스와 Skills를 갖춘 뒤 정형화된 단순 화면에 한정해 활용을 검토합니다.

4. 기대 효과

  • 참조 범위 밖의 코드 생성을 차단하여 화면 오류와 검수 공수를 줄입니다.
  • 컴포넌트 선택 기준을 표준화하여 모델에 관계없이 결과물이 일관되게 나옵니다.
  • 규칙을 Skill로 자산화하여 모델이나 담당자가 바뀌어도 품질을 재현할 수 있습니다.
